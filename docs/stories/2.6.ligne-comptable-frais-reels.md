# Story 2.6 : Ligne comptable avec les frais réels

## Status

Draft

## Story

**As a** trésorier de l'association,
**I want** que chaque encaissement porte les frais réellement prélevés par Stripe,
**so that** le montant reversé à la fondation soit exact et rapprochable au centime.

## Acceptance Criteria

1. La ligne comptable porte : brut, **frais réels Stripe**, net, part reversée, part
   contrepartie.
2. Les frais sont **récupérés auprès de Stripe**, jamais estimés (D12).
3. Les frais peuvent arriver **après** le paiement : la ligne est complétée quand ils sont
   connus, sans jamais être réécrite sur ses autres colonnes.
4. La ligne porte les identifiants Stripe permettant le rapprochement avec le relevé.
5. Une ligne dont les frais ne sont pas encore connus est identifiable, pas silencieuse.
6. La somme des parts reversées est consultable depuis le back-office.

## Tasks / Subtasks

- [ ] Récupérer la transaction Stripe et ses frais (AC: 2, 3)
- [ ] Compléter la ligne comptable (AC: 1, 3, 4)
- [ ] Signaler les lignes incomplètes (AC: 5)
- [ ] Totaux dans le back-office (AC: 6)

## Dev Notes

**Pourquoi les frais réels et pas une estimation** (D12, NFR15). Les frais Stripe varient :
carte européenne ou non, carte professionnelle, moyen de paiement. Une estimation à 1,4 % +
0,25 € est fausse pour une partie des paiements, et l'écart se voit sur le relevé — au
moment où l'association doit justifier son reversement.

**Ils n'arrivent pas tout de suite.** Le webhook de paiement ne les connaît pas encore : ils
sont portés par la transaction de solde (`balance_transaction`), disponible un peu après.
D'où l'AC 3 — la ligne se complète, sans que le reste bouge (l'immuabilité de la story 2.1
porte sur les montants déjà écrits, pas sur une colonne encore vide).

**Une ligne incomplète doit se voir** (AC 5). Une colonne de frais à zéro qui ne dit pas
qu'elle est provisoire produit un total faux — et un total faux qu'on croit juste est pire
qu'un total manquant.

**Le lien avec « 100 % reversé »** : c'est cette story qui donnera le chiffre exact et
permettra de trancher la décision P2 du PRD sur des données plutôt que sur une estimation.

### Testing

- Rapprocher trois paiements de test avec le relevé Stripe, au centime.
- Vérifier qu'une ligne sans frais connus est signalée.
- Vérifier qu'un rejeu ne double aucune colonne.
