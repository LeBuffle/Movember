# Story 9.9 : Seuils de détection paramétrables

## Status

Draft

## Story

**As a** bénévole de l'organisation,
**I want** ajuster les seuils qui déclenchent un signalement,
**so that** je puisse corriger un excès de faux positifs sans redéploiement.

## Acceptance Criteria

1. Les seuils des règles de cohérence vivent **en base**, pas dans le code.
2. Ils sont modifiables sans redéploiement.
3. Une valeur par défaut raisonnable existe pour chaque règle.
4. Une modification prend effet sur les activités suivantes, pas rétroactivement.

## Tasks / Subtasks

- [ ] Table de seuils et valeurs par défaut (AC: 1, 3)
- [ ] Lecture des seuils par les règles (AC: 2, 4)

## Dev Notes

**Même raisonnement que l'exposant du classement d'équipe** (story 7.5) : un réglage qui
sera discuté en novembre ne doit pas demander un développeur. Un excès de faux positifs le
troisième jour se corrige en une commande.

**Pas rétroactif.** Rejuger les activités passées à chaque changement de seuil ferait
apparaître et disparaître des cas dans la file d'arbitrage, ce qui est le meilleur moyen de
faire perdre confiance en elle.

### Testing

- Modifier un seuil en base et vérifier que la règle suivante l'utilise.
