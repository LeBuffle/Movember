# Story 5.2 : Moteur de tirage pondéré par rareté

## Status

Review

## Story

**As a** participant,
**I want** que la carte reçue soit une vraie surprise,
**so that** ouvrir une carte reste un plaisir pendant trente jours.

## Acceptance Criteria

1. Le tirage choisit une rareté selon les poids en base, puis une carte dans cette rareté.
2. La **difficulté du défi n'influence pas la rareté** (PRD D9).
3. Une rareté sans carte publiée disponible retombe sur la rareté inférieure plutôt que
   d'échouer.
4. Le tirage privilégie une carte que le participant n'a pas encore, sans l'imposer.
5. Le tirage est une **fonction pure**, testable sans base de données.
6. Un **test statistique** vérifie que les probabilités observées correspondent aux poids.

## Tasks / Subtasks

- [x] Sélection de la rareté (AC: 1, 2)
- [x] Repli si la rareté est vide (AC: 3)
- [x] Préférence pour une carte manquante (AC: 4)
- [x] Test statistique (AC: 5, 6)

## Dev Notes

**La difficulté ne détermine pas la rareté** (PRD D9). C'est contre-intuitif et c'est
délibéré : lier les deux ferait des défis faciles une source de cartes sans valeur, et le
participant le moins sportif collectionnerait du vide.

**La légendaire reste accessible gratuitement.** Elle n'est *garantie* que par le bonus du
niveau 3, mais le tirage peut en produire — proposition : 2 %. Une rareté strictement payante
contredirait « aucun avantage acheté ».

**Préférer une carte manquante sans l'imposer** (AC 4) : recevoir un doublon fait partie du
jeu, en recevoir cinq d'affilée le tue.

### Testing

- Tirer dix mille fois et comparer la répartition aux poids.
- Vérifier le repli quand une rareté n'a aucune carte publiée.
