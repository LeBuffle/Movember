# Story 7.1 : Schéma des équipes et adhésion par code ou lien

## Status

Review

## Story

**As a** participant,
**I want** rejoindre l'équipe de mon club ou de mon entreprise,
**so that** on joue ensemble au lieu de chacun dans son coin.

## Acceptance Criteria

1. Un participant crée une équipe ou en rejoint une **par code ou par lien** (FR69).
2. Un participant n'appartient qu'à **une seule équipe** par édition.
3. Le code d'adhésion est court, lisible à voix haute, et **impossible à deviner**.
4. Rejoindre deux fois la même équipe ne crée pas deux adhésions.
5. Un code qui ne correspond à rien est refusé par une phrase, jamais par une erreur.
6. Les équipes sont lisibles par les participants de l'édition ; personne ne peut écrire
   l'adhésion d'un autre.
7. Une équipe porte un type : libre, entreprise ou association.

## Dev Notes

**Les équipes sont le principal levier de croissance de cette édition** : elles permettent
d'embarquer une association ou une entreprise d'un bloc.

**Le code se lit à voix haute dans un vestiaire.** Ni `0`/`O` ni `1`/`I`/`l` : un code
qu'on épelle mal est un participant perdu.

**Une seule équipe par participant et par édition**, sans quoi le classement d'équipe ne
veut plus rien dire.

### Testing

- Créer une équipe, la rejoindre avec un second compte, vérifier une seule adhésion.
- Rejoindre deux fois, vérifier qu'il n'y a pas de doublon.
- Essayer un code inventé.

## Dev Agent Record

### Décisions prises

**Le code d'adhésion est un secret, et la sécurité au niveau des lignes ne sait pas garder
un secret dans une colonne.** C'est le même piège que celui de `public_profiles` à la story
1.6, et il a la même réponse. Autoriser les participants à lire la table `teams` pour
afficher les noms d'équipe leur donnerait du même coup **tous les codes** — et rejoindre
cesserait d'être une décision du capitaine. La table reste donc privée, lisible seulement
par son capitaine, et une vue `public_teams` expose le nom, le type et rien d'autre.

**Aucune politique d'écriture, sur aucune des deux tables.** Celle-ci mérite d'être écrite,
parce qu'un participant qui écrit sa propre ligne d'adhésion a l'air inoffensif. Il ne
l'est pas : la sécurité au niveau des lignes sait vérifier « cette ligne est la vôtre »,
elle ne sait pas vérifier « vous connaissiez le code ». Une politique autorisant
`auth.uid() = profile_id` laisserait donc entrer n'importe qui dans n'importe quelle équipe
par simple identifiant — le contrôle du capitaine serait décoratif, et le classement
d'équipe ouvert à qui voudrait s'asseoir dans l'équipe de tête.

**L'alphabet du code est décidé par un fait concret : il se lit à voix haute dans un
vestiaire, ou se photographie sur un tableau blanc.** Ni `O` contre `0`, ni `I` ou `L`
contre `1`. Exclure ces caractères vaut mieux que d'essayer de les corriger après coup : si
`O` ne peut jamais apparaître, quelqu'un qui en tape un a mal lu quelque chose, et rien ne
permet de savoir quoi. La réponse honnête est « ce code n'existe pas », et l'alphabet est ce
qui rend ce cas rare. Huit caractères, soit environ 850 milliards de combinaisons — pas un
mot de passe, mais impossible à deviner au hasard.

**La normalisation pardonne ce que tout le monde rate** — la casse, les espaces, le tiret
de la forme affichée — et rien d'autre.

**Une seule équipe par participant, garantie par un index unique.** Sans elle, quelqu'un
présent dans trois équipes compterait trois fois, et le classement d'équipe serait une
absurdité arithmétique que personne ne saurait expliquer. `edition_id` est porté sur
`team_members` en plus de l'équipe : ce n'est pas une redondance, c'est ce qui rend la règle
exprimable comme un index plutôt que comme une vérification que le code se rappelle de
faire.

**C'est la base qui tranche les noms en double, pas une vérification préalable.** Deux
personnes créant « Les Moustachus » à la même seconde passent toutes les deux un contrôle
fait un instant plus tôt ; une seule passe l'index unique.

**Rejoindre deux fois la même équipe est un succès, pas un refus.** L'index unique répond
par le même code d'erreur dans deux situations qui se lisent très différemment — déjà dans
*cette* équipe, ou déjà dans une autre — et la seconde requête sert uniquement à les
distinguer.

**Créer une équipe rend capitaine dans le même geste.** Une équipe sans capitaine est une
équipe que l'organisation devra adopter à la main, en novembre. Et si l'adhésion du
capitaine échoue, l'équipe est supprimée : une équipe vide dans toutes les listes est pire
qu'une création ratée qu'on peut simplement recommencer.

### Ce que cette story ne fait pas

- **Pas de départ ni d'exclusion.** C'est la story 7.2, avec la question du capitaine qui
  part sans successeur.
- **Pas de classement d'équipe.** C'est la story 7.5. L'écran le dit, pour que personne ne
  cherche un onglet qui n'existe pas encore.
- **Pas d'adhésion par lien en un clic.** Le lien est affiché et porte le code, mais il
  amène sur l'écran plutôt que d'inscrire directement : un lien qui inscrit au chargement
  s'active tout seul quand une messagerie le prévisualise.
- **Pas de création d'équipe depuis le back-office** (FR78). C'est la story 7.2.
- **Pas de page d'équipe.** C'est la story 7.9, priorité S.
