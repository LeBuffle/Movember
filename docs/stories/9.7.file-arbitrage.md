# Story 9.7 : File d'arbitrage des activités signalées

## Status

Review

## Story

**As a** bénévole de l'organisation,
**I want** trancher un cas signalé en deux clics,
**so that** la file ne s'accumule pas jusqu'à devenir ingérable.

## Acceptance Criteria

1. Les activités signalées apparaissent dans une file d'arbitrage (FR102).
2. Chaque cas montre la règle déclenchée, la valeur constatée et le participant.
3. L'administrateur **accepte** ou **écarte** en un geste, avec un motif.
4. Un cas tranché quitte la file et **ne revient jamais**.
5. Chaque décision est journalisée avec son auteur et son motif.
6. Écarter une activité **n'invalide pas** le défi : c'est un geste distinct (story 4.10).
7. Une file vide se dit — c'est l'état normal et souhaitable.

## Dev Notes

**Deux clics, sinon la file gagne.** Une file d'arbitrage qui demande de comprendre un
formulaire est une file qu'on regarde le premier jour et qu'on abandonne le troisième.

**Écarter n'invalide pas le défi**, et la séparation est délibérée — la même que pour la
suspension et le remboursement. Juger une activité et retirer des points à quelqu'un sont
deux décisions ; les confondre dans un bouton, c'est prendre la seconde sans l'avoir voulu.

**Un cas tranché ne revient jamais**, même si la même activité est resynchronisée.

## Dev Agent Record

### Décisions prises

**Deux clics, et le motif est le second.** « Valable » ou « écarter », une phrase, confirmer.
Une file qui demande de comprendre un formulaire est une file qu'on regarde le premier jour
et qu'on abandonne le troisième — et une file abandonnée est pire que pas de file, parce
qu'elle donne l'impression que le jeu est surveillé alors qu'il ne l'est plus.

**Écarter n'invalide pas le défi**, et l'écran le rappelle sur chaque cas. C'est la même
séparation que la suspension et le remboursement : juger une activité et retirer des points
à quelqu'un sont deux décisions, et les confondre dans un bouton c'est prendre la seconde
sans l'avoir voulu. Retirer des points passe par l'arbitrage des défis (story 4.10), avec
son propre motif et sa propre trace.

**Du plus ancien au plus récent.** Un cas laissé trois semaines est un cas dont plus
personne ne se rappelle le contexte ; cette file existe pour être vidée, pas pour être
parcourue.

**La garde est portée par l'écriture** (`status = 'pending'`) : un cas tranché ne se
retranche pas, et deux bénévoles sur deux téléphones ne s'écrasent pas.

**Un cas tranché ne revient jamais**, même si l'activité est resynchronisée : l'index
unique sur (activité, règle) s'en charge, et le code traite la violation d'unicité comme le
résultat normal qu'elle est.

**Les participants sont nommés par leur pseudonyme**, lu dans la vue publique. L'arbitre qui
a besoin d'écrire à quelqu'un a la fiche participant pour ça.

**Une file vide s'annonce comme une bonne nouvelle.** La plupart du mois elle sera vide, et
c'est le résultat qu'on espère : il veut dire que les règles ne produisent pas de faux
positifs.

**L'accueil du back-office alerte quand la file grossit**, avec un lien direct. Sans ça,
elle serait découverte en décembre.

### Ce que cette story ne fait pas

- **Pas d'action groupée.** Trancher dix cas d'un coup, c'est trancher sans regarder.
- **Pas de réouverture d'un cas tranché.** Si une décision était mauvaise, le journal la
  porte et l'arbitrage des défis permet de corriger l'effet.
- **Pas de vue des cas déjà tranchés.** Ils sont dans le journal, qui est fait pour ça.
