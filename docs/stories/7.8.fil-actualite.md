# Story 7.8 : Fil d'actualité et publication depuis le back-office

## Status

Review

## Story

**As a** administrateur,
**I want** publier un message aux participants depuis mon téléphone,
**so that** le mois soit animé sans passer par un développeur.

## Acceptance Criteria

1. L'administrateur publie un message avec **texte et image**, depuis son téléphone.
2. Le fil est visible par les participants dans l'application.
3. Un message peut être **épinglé** en tête de fil.
4. Un message publié peut être modifié ou dépublié.
5. Chaque publication est journalisée.
6. Un fil vide se dit, plutôt que d'afficher une page blanche.
7. Publier ne déclenche **pas** automatiquement une notification : les deux sont des
   gestes distincts.

## Dev Agent Record

### Décisions prises

**Publier n'envoie aucune notification, et l'écran le dit.** Le fil est le canal calme ;
la notification est celui qui interrompt. Les lier automatiquement transformerait chaque
petite annonce en interruption — et c'est ainsi qu'on fait couper les notifications, donc
qu'on perd aussi le rappel du défi du jour. Deux gestes distincts, et une phrase sous le
bouton pour que personne ne suppose le contraire. Un test vérifie qu'aucune action de
publication n'appelle le répartiteur de notifications.

**Un brouillon est invisible parce que la base le refuse, pas parce que l'écran l'omet.**
La règle de lecture des participants porte `published_at is not null` : un défaut dans un
filtre applicatif ferait apparaître un message non relu, pas une page cassée — c'est le
genre d'erreur qu'on ne voit qu'une fois qu'elle est publique.

**Le fil n'est pas lisible sans compte.** Une annonce sur un défi ne veut rien dire pour un
visiteur, et un fil public serait indexé par les moteurs de recherche. Aucune règle
n'ouvre la table à `anon`, et un test le vérifie.

**Un message se dépublie, il ne se supprime pas.** « Pourquoi ce message a disparu » est une
question qui se pose, et la réponse doit exister. La ligne reste, invisible des
participants. Aucune suppression n'existe dans le code — testé.

**La garde est portée par l'écriture.** Publier exige `published_at is null`, dépublier
exige l'inverse. Deux bénévoles sur deux téléphones ne peuvent pas tous les deux croire
avoir publié, et une seconde pression ne repousse pas discrètement la date de publication.

**L'image est téléversée avant l'écriture, jamais après** — même ordre et même raison que
le catalogue de cartes : dans l'autre sens, on enregistre un message dont l'auteur croit
qu'il a son image. Le stockage est celui de la story 5.6 ; les fonctions ont été renommées
`uploadImage` / `removeImage` puisqu'elles ne servent plus qu'aux cartes.

**L'écran est pensé pour un téléphone**, parce que c'est là que l'animation de novembre se
fera : dans un train, entre deux réunions. Formulaire court, champ fichier ordinaire, et un
aperçu qui rend exactement ce que le fil rendra — même absence de mise en forme, mêmes
retours à la ligne conservés. Un aperçu plus joli que le résultat serait une promesse non
tenue.

**Le texte est rendu comme du texte.** `whitespace-pre-line`, aucun `dangerouslySetInnerHTML` :
une apostrophe ou un « < » dans un message ne peut devenir autre chose. Testé.

**Épinglé d'abord, puis le plus récent** dans le fil ; brouillons d'abord dans le
back-office, parce que ce sont eux qui attendent une action.

**Chaque geste est journalisé** : `news.created`, `news.updated`, `news.published`,
`news.unpublished`, avec vérification du rôle avant l'écriture et avant le journal.

### Ce que cette story ne fait pas

- **Pas de commentaires ni de réactions.** Le fil est descendant. Modérer des commentaires
  pendant novembre serait une charge que personne n'a prévu de porter.
- **Pas de programmation à l'avance.** Publier est un geste manuel.
- **Pas de mise en forme riche** : ni gras, ni liens cliquables dans le corps du message.
  Le rendu serait à sécuriser et l'éditeur à écrire, pour un gain faible.
- **Pas de notification depuis cet écran** — c'est le sujet, et l'écran des notifications
  (story 6.8) est là pour ça.
